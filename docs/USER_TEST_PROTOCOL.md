# Protocole de test utilisateur — première leçon HTML

Source : adaptation du document externe `PulsaTeach-Tests-Utilisateurs.md` fourni le 17 novembre 2026. L'audit expert `PulsaTeach-Audit.md` porte sur une navigation sans compte sur Chrome ordinateur ; sa note de 7/10 est une appréciation de cet auteur, pas une mesure d'utilisateurs. **Aucune session humaine n'a encore été menée ici.**

## Recrutement et déroulé

- Cinq personnes découvrant cet exercice : trois débutants complets et deux ayant déjà écrit une page HTML. Comparer des profils similaires pour une deuxième version.
- Profil vierge, première passe sur ordinateur ; séances tactiles distinctes. Durée visée : 20 minutes. Demander l'accord avant tout enregistrement.
- Sans guider les clics : « Tu veux apprendre à créer ta première page web. Montre-moi comment tu commencerais. » Puis : « Essaie de réussir le premier exercice. Dis à voix haute ce que tu cherches et ce que tu comprends. »
- Après une réussite ou un blocage prolongé : « Que ferais-tu pour continuer ? Où penses-tu que ton code est enregistré ? » Dans une séance dédiée, partir du catalogue et demander d'estimer le premier module.
- Autoriser les aides intégrées. Après cinq minutes de blocage, une relance neutre est permise et consignée. Distinguer aide du produit, relance du modérateur, abandon et validation autonome.

## Restitution

Rapporter les comptes bruts : validations autonomes / nombre total, abandons, points de blocage et nombre de personnes ayant atteint la validation. Calculer la médiane du temps jusqu'au premier test réussi **après modification** parmi ces dernières, avec son dénominateur. Le 3/5 du starter n'est pas une réussite apprenant. Ne pas présenter la note expert ou les tests automatisés comme un taux de réussite humain.

Comparer notamment les hypothèses suivantes : hésitation devant la durée et les compteurs (PT-01), possibilité d'agir après le premier échec (PT-02), peur de perdre le code ou confusion entre fusion et progression (PT-03). Pour chaque correction, conserver observation, verbatim anonymisé, sévérité, fréquence réellement observée et condition de retest. Si une instrumentation est ajoutée, enregistrer clic, ouverture, première modification, test et validation uniques par session/étape, sans enregistrer le code.
